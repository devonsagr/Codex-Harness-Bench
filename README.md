# Codex Harness Bench

**在 Codex 桌面既有底座上，评测模型与个人配置共同产生的真实交付。**

你可能为 Codex 写了 AGENTS 规则、装了 Skills、换了模型与思考档位，却很难回答一个实际问题：这套配置是否更能完成你每天交给它的任务？一次漂亮的演示不能证明改动稳定有效；公开模型榜单也没有测试你电脑上的个人配置。

Codex Harness Bench 把“个人配置版本 → 固定任务与源码起点 → Codex 桌面实际交付 → 回收文件与验收证据”连成一条可追溯记录。编码 benchmark 通常也带有指定的 Agent/Harness；这里固定日常桌面场景，重点研究用户可配置的那一层，同时保留模型与宿主条件，避免把组合差异错认成某条规则的功劳。

```text
Codex 桌面底座 + 模型/推理档位 + 个人配置
                       ↓
              同一任务与源码起点
                       ↓
         实际交付 → 机器验收 → 人工按需修正
                       ↓
            配置之间有条件、可追溯的比较
```

日常需求往往是产品经理交代一个想法，让 AI 把它落地；标准题高分不保证这种开放任务的体验同样好。因此这里同时观察基准任务和真实项目，而不把用户的主观使用感受写成某个模型普遍优劣的结论。

比较个人配置时，尽量保持模型、桌面版本、题目、环境与评分方式相同。换模型也可以，但那是在比较整套组合。重复多题后再判断收益，单次高分不能证明一条规则有效。

## 两种评测，分别解释

|方向|主要依据|怎样看分数|
|---|---|---|
|基准验证|固定题目、源码、环境与原题验收器|测试通过/失败及原判分协议优先；AI 质量评价是补充|
|真实项目交付|产品意图、实际交付、可运行行为、界面体验|AI 量表＋人工实际复核，允许多种合理实现，具有主观性|

这不是“修 Bug / 新建项目”的二分。已有工程扩展也可以是基准题，真实产品也需要测试。当前界面依据公开题源和声明的检查展示主要判分依据，保留历史冻结政策。未接通原验收器会明确标注，不能用 AI 分冒充上游成绩。

**所有评分仅供特定条件下参考，不代表模型的全面能力或每次真实表现。** AI 与人工都可能有偏差；不同协议的百分比、质量分、排名分不直接互换，也不混成官方跑分。

公开基准的裁判方式并不统一：有的以程序验收为主，有的结合专家量表、AI 或人工复核。因此本项目保留原题验收、质量参考评价和人工证据的区别，具体公开方法见[研究记录](docs/research/benchmark-scoring-20260923.md)。

## 能做什么

- 保存、导入、复制和归档配置；归档可恢复，也可在回收站或配置成绩中永久删除。历史评测保留创建时冻结的配置副本。
- 管理 AGENTS、真实技能文件、模型/档位、交互约定和支持的原生设置；显式应用到 Codex 时备份、回读并可撤销。
- 创建独立 Git 工作区，自动放入已绑定源码、已有测试及所选规则；在 Codex 桌面完成正式执行。
- 回收产物快照，启动独立机器裁判，选择思考档位与审查预算，查看实际提示词、公开进度、命令及证据。
- 人工复核可查看快照文件和图片、创建独立运行副本；不依赖 AI 成功也能保存绑定版本的人工参考分。机器原分、人工修正与独立人工评价分存。
- 自动保护首次启用时的 Codex 配置和规则原文件，显式恢复前再备份；不备份认证文件。
- 从匹配工作区的原生日志读取 Token、缓存和活动时间，保存历史并导出本地 ZIP。

这是持续开发中的本地工作台。**公开题库批量环境适配、Windows 本机裁判的浏览器取证、评分可靠性校准仍未完成。** 当前功能与路线见[总架构](docs/PROJECT_SPEC.md)、[当前交接](docs/当前交接.md)。

## 启动

需要 Python 3.12+、uv、Node.js 和 pnpm；正式执行需要已安装并登录 Codex 桌面。

```powershell
uv venv --python 3.13
uv sync --frozen
pnpm --dir frontend install --frozen-lockfile
pnpm --dir frontend build
.venv\Scripts\python.exe -X utf8 -m chb.cli ui
```

Windows 也可双击 **launch-ui.cmd**。首次缺 Python 环境时自动执行 `uv sync --frozen`；缺前端构建时安装锁定依赖并构建。需要 uv、Node.js 和 pnpm 已可用。默认地址 **http://127.0.0.1:8765**，只监听本机；启动进程需保持运行。可加 `--port 8766` 或 `--no-browser`。更新源码后重新构建前端。

Linux/macOS 将 Python 路径换为 `.venv/bin/python`；目前实机验证以 Windows 为主。支持源码仓库 editable 安装，独立 wheel 不含完整题库及前端，也尚无免依赖桌面安装包。

**Docker 不是网站或桌面执行的前置条件。** 本机裁判也不要求 Docker；外部题包、独立脚本验收或 Harbor 裁判若依赖容器，则需要 Docker Linux 引擎和相应镜像。不能把容器内的运行条件直接当成 Windows 本机条件。

## 一次评测怎么做

1. **保存配置。** 选模型、推理档位、标准或 Fast 速度、规则和 Skills。导入到工作台只保存副本；点击“应用到 Codex”才会写入宿主设置。创建新评测时也会把所选速度写入独立工作区。已开启的任务不保证即时采用新设置。
2. **选择任务。** 从零开发看完整需求；修复、重构或已有工程扩展还必须有源码起点。题目页显示文件、来源和环境要求。
3. **准备并执行。** 自动生成独立目录及任务草稿，在 Codex 桌面核对目录、配置和提示词后发送。默认给出完整需求，不限定真实对话轮数；继续修改就在原任务中进行。
4. **回收并评分。** 交付就绪后停止文件写入，回收产物，再点击自动检查并评分。查看机器分、必要需求结论和证据；有异议时按项修正。
5. **结束与比较。** 标记交付结束，保存配置版本、产物与评分记录。对比另一配置时使用相同任务和条件。分阶段执行仅在主动选择时使用。

配置归档位于编辑器顶部；回收站在配置列表下方。已归档配置可在回收站或“配置成绩”中永久删除，移除该配置的成绩卡和配置库版本，但不会撤销已经应用的宿主设置，也不删除既有评测的冻结副本、产物或评分。

## 配置成绩与批量评测

一套已保存配置可选多道题创建评测。一次批量创建对应一条评测记录，每题各有试次、独立工作区、Git 起点和回收记录；人在 Codex 桌面逐项打开与执行。同机的全局 Codex 设置仍共享，因此手动并发不保证互不影响。相同仓库提交校验后复用只读缓存，重复测试仍使用新的可写工作区。

“配置成绩”按配置 ID 和保存版本分组，默认显示当前版本，可筛选历史和已归档配置。外层显示交付结束次数、最终评分次数和可核对题目数；交付结束并不意味着已经评分。同一道题、同一版本的重复测试可取均值，不同题目难度和验收协议不同，**不生成跨题总均分**。展开后按来源查看逐题历史。归档配置及评测仍保留成绩；从历史列表移出的记录不参与成绩，但文件与内部索引保留且可恢复。配置修改后由新版本接续，旧版作为历史版本保留。评分方案、AI 裁判协议或执行条件不同的记录不合算。

要比较两套 Harness，应选相同题目和版本，并对齐模型、思考档位、速度、评分方案、裁判协议及桌面条件。即便共同题相同，随机性、样本量和人工判断仍可能影响结果；本站不输出统计置信区间或官方榜单。

配置库是规则、Skills、模型、思考档位与速度的编辑入口。点击“应用到 Codex”会备份并写入所选设置，写入后可核对和撤销；新桌面任务仍须确认实际模型与档位，因为已有对话及项目级覆盖不随全局文件自动切换。

任务库与评测工作台共用 DeepSWE 题目索引，未下载的题也可选，不必先导入。创建评测时只下载所选题的题面、环境定义、隐藏验收与固定源码，并显示按题目计算的准备进度；这不是下载字节百分比。固定来源版本 `0b9fabbb63b9104d678fe965e1632f2dd9eaa2ea`，共4道Bug修复、106道功能扩展、3道工程改进，每次最多10题。可按任务类型和项目语言筛选；公开题没有统一难度标签时不猜测难度。**源码可用、本机环境可用、原测试可用分别标明；其他题的依赖仍待适配。** 超限或下载失败时保留已验证缓存，不生成空工程冒充成功。

目前自动准备与程序验收支持三题。创建时校验项目内固定Go工具链与故障起点；回收后，在“评分 → 项目测试验收”运行隐藏测试并查逐组日志。

内置题不需要用户再次导入，创建评测时自动复制源码和已有测试；参考解和隐藏验收器不交给被测任务。自定义起点支持本地目录或公开 GitHub 仓库的完整 commit SHA。题目、源码和评分方案均按版本冻结。

公开来源的调查和取舍见[调研依据](docs/research/landscape.md)，题目索引来源与许可见[catalog说明](catalog/SOURCES.md)。

## 数据、缓存与清理

同一仓库、同一提交的源码只缓存一次。每次评测都从缓存复制到新的 `runs/<runId>/<trialId>/workspace/` 并建立独立Git起点，绝不复用之前做过的目录；不同题共享同一仓库起点也不会共享可写文件。清除缓存或更换源码提交才需要重新下载。

“评测历史”每条记录直接提供三类操作：清理可写工作区文件，保留回收快照与评分；移出历史列表，保留文件和内部索引但不计入配置成绩，可在“已移出”页恢复；彻底删除整次评测及其文件和记录。活动、归档、已移出记录均可从这里操作。工作区清理仍要求交付结束、产物已回收且桌面不再写入，先移入待删除区，再确认永久删除；未回收改动或后台检查会阻止清理。

|本机目录（均在 `.local/arena/`）|用途|
|---|---|
|`arena.sqlite3`|配置/题目版本、历史与评分索引|
|`public-sources/`、`baselines/`|固定公开题包、目标源码起点；隐藏验收与开发起点分开|
|`runs/<run>/<trial>/workspace`|桌面任务可修改的副本|
|同一试次的 `captures/`、`reviews/`|回收快照和独立复查材料/结果|
|`reviewer-runtime/`、`downloads/`|临时裁判目录与下载暂存；正常结束清理|
|`trash/workspaces/`|可恢复的待删除工作目录|

私有数据与下载文件不进入公开 Git；清理不触碰宿主 Codex 的登录和全局技能。共享源码缓存和初始配置备份继续保留。本站目前无法可靠地把通过深链新建的 Codex 对话 ID 与评测记录一一对应，也没有永久删除 Codex 任务的受支持接口，因此**不会声称清理本项目文件会同步删除桌面侧栏任务**；这些任务仍需在 Codex 中单独管理。手动导出的 ZIP 也不在清理范围。

## 怎样打分

**程序验证提供事实，独立 AI 评价开放质量，人工修正分歧。**

- 对有原生验收器的公开题，应保留其通过/失败及原生指标；不把AI印象分当成官方benchmark分。
- 对开放需求，裁判在产物副本上读取需求、运行可用检查并主动取证，按需求完成、健壮性、交互、交付和维护等维度给出有引用的分数。没有专用脚本也可发起，但无法验证的项保持为空。
- 当前默认权重为50/20/15/10/5，属于可调整的产品约定。非界面题排除交互维度后归一；必要需求的验收结论单列，不能由其他高分抵销。
- 人工可独立审查回收产物，也可修正机器评分中有异议的项；两种记录分别保存，保留原分、理由和版本。完整机器覆盖且交付结束后才形成最终分；覆盖不足时显示暂定分。机器覆盖率不是测试覆盖率。

通用的是取证流程和评分量表，每个任务仍有自己的成功条件。程序通过率、质量分、约束遵守和资源使用分别解释。模型裁判会有波动与偏差；新会话和有效引用不等于判断正确。本项目尚未完成可靠性校准，也不把一次结果包装成统计结论。

**前端交互与视觉需要真实浏览器操作和截图证据。** Windows本机裁判的浏览器取证尚未打通，不能只读源码就宣称交互/视觉已经验证。

### 本机裁判与可选容器检查

本机裁判使用独立 Codex CLI 进程和产物副本，与正式桌面执行分开。需要自行安装并登录官方 CLI；通过 `PATH` 查找 `codex`，非标准路径可设置 `CHB_CODEX_BIN`。可在终端检查 `codex --version` 和 `codex login status`。

默认裁判为 `gpt-6-luna` / `max`，不可用时需明确选择可用模型。更换裁判模型、档位或项目裁判提示词版本会改变成绩可比条件；不将默认模型当作评分准确的保证。本站 AI 质量参考使用项目编写并标记版本的提示词，不是 DeepSWE 官方打分提示词；DeepSWE 原题主判分使用其隔离程序验证器。AI 报告中的命令引用若无法与保存日志对应，该维度保持未验证，不代表 Docker 缺失或程序失败。本机裁判使用启动时 Codex CLI 连接对应的额度或 API 账单，仓库不提供模型额度；不假定桌面与 CLI 登录相同。每次裁判不续接旧会话，过程面板保留实际命令、输出与失败信息。

可选独立验收镜像：

```powershell
.venv\Scripts\python.exe -X utf8 -m chb.cli prepare --checks-only
.venv\Scripts\python.exe -X utf8 -m chb.cli prepare --checks-only --task storage-migration-v1
.venv\Scripts\python.exe -X utf8 -m chb.cli prepare --checks-only --task csv-catalog-v1
.venv\Scripts\python.exe -X utf8 scripts/prepare_arena_review.py
```

上面准备容器镜像，不启动正式模型任务。固定检查在无网络容器的快照副本执行；本机裁判不启动这些容器脚本。检查定义与证据规则见[评分合同](docs/architecture/EVALUATION.md)。

## 记录与问题排查

业务数据保存在 `.local/arena/` 的 SQLite、冻结文件与日志中；localStorage 只存外观偏好。私有配置、原生日志和产物不提交 Git。ZIP 可含个人规则与产物，仅供用户本地导出；归档可恢复。

独立工作区仍可能继承桌面全局规则、技能和插件。宿主指纹只覆盖部分条件；严格同条件分组需要更多证据，本机裁判结果目前不纳入严格比较。

用量读取匹配cwd/session的日志累计值；缓存属于输入Token，不重复加总。无法确认的时长、费用保持未知。环境错误、额度不足和中断不冒充任务失败或零分。

出现 `Failed to fetch` 时检查本地服务是否仍运行。重启服务后先保留草稿，再重新加载页面；到历史核对已保存结果，避免重复提交。断连不会删除数据库或已生成的工作区文件。
