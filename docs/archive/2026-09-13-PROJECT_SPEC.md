# Codex Harness Bench

本地运行的 Codex 配置实验工具。保存配置、固定实验条件、运行同一组公开工程任务，以独立验收判断交付是否正确，保留结果供恢复和复测。

需求原文和 R01–R23 只保存在 [requirements.md](requirements.md)。本文件描述实现合同，不把旧对话中模型提出的设想当成已实现功能。

## 产品判断

可做。市场上已有 skills、AGENTS.md 和 coding agent 的评测项目，因此价值在于面向个人 Codex 配置的清晰实验闭环：**改了什么 → 生效了什么 → 做成了什么 → 用了多少 → 差异能否相信 → 如何重跑**。

已实现的技术底座使用 Harbor 的 Codex adapter、Docker 生命周期、网络控制、单独验收环境和轨迹采集，本项目已有冻结配置、控制变量、运行顺序和中文静态报告。F1 本地前端已接通配置、计划与历史；页面运行控制和实时状态属于尚未完成的 F2。R20–R23 的阶段验收见下文及 [路线图](ROADMAP.md)。既有能力与缺口见 [调研](research/landscape.md)。

## 首轮范围

助手此前按“两套配置、一题、一次对比”实施了技术验证；用户要求远端连接不要阻碍本地工作。这是已发生的实施范围，不代表用户审查同意了完整产品路线。用户原话与本次纠偏见 R20–R22。

- 两套示例：minimal / focused。它们不是用户整套个人配置的镜像，也不是 superpowers 的对照实验。
- 一个原创 Python 笔记搜索任务，验收 Unicode、标签、归档过滤、空查询、输入保真和既有工具复用。
- 固定 Codex CLI 0.154.0、Harbor 0.23.0、模型请求标识、推理档位、镜像内容、任务和预算。
- 执行器提供一次性真实运行，失败保留结果；报告能离线重建。
- 首轮当时保留本地；U06 后题源源码随项目上传指定 GitHub 仓库。仓库公开可见性未核实，不宣称已有公开基准成绩。

退出标准：错误起点被拒绝，参考解通过；两个 profile 实际装载内容可核对；两次 Codex 调用在独立容器中完成；候选产物在另一容器验收；结果、时长、用量、配置差异可查看。服务或环境失败必须如实记录，不能用模拟结果替代。

## 架构

```mermaid
flowchart LR
    P[可编辑配置] --> S[内容哈希快照]
    T[任务与验收定义] --> S
    S --> E[冻结实验计划]
    E --> H[Harbor + Codex]
    H --> C[独立工作容器]
    C --> A[完整候选目录]
    A --> V[全新验收容器]
    V --> R[JSON 结果与本地 HTML]
    H --> R
```

代码边界：

- `profiles.py`：严格限定输入、拒绝凭据文件和链接、按文件 SHA-256 生成内容摘要。
- `configuration.py`：私有配置部分导入、显式技能添加、复制与从实验快照恢复。
- `cli.py`：预检、镜像准备与保留、配置差异、实验冻结、顺序调度 Harbor。
- `experiments.py`：新旧计划的任务路由、全量题目核验、确定性顺序和按组配对汇总。
- `results.py`：终止事件、逐轮验收、同一 session ID、skill 完整读取输出等证据提取。
- `usage.py`：核对原生累计记录与 CLI 上报，生成逐轮增量、总量及不可用原因。
- `analysis.py`：读取已结束实验，新增独立分析目录、来源清单和分析代码快照，不写回原结果。
- `adapter.py`：扩展 Harbor Codex，仅注入全局 AGENTS.md 与可选 skill 文件，保存装载证据。
- `webapp.py` 与 `web/`：仅本机 HTTP 接口与五页工作台，复用配置和实验函数；前端没有独立数据库，F1 不暴露 run/stop 动作。
- `report.py`：转义后输出本地 HTML，不创建服务。
- `tasks/`：原创题面、基础代码、参考解、外部验收器。只把 environment/fixture 放进 agent 镜像。

本地 UI 使用 Python 标准库 ThreadingHTTPServer 和原生 HTML/CSS/JavaScript，无新增第三方依赖、数据库、队列或账号系统。页面读写现有文件，Harbor 仍负责执行层。

界面读取同一套 profiles/runs 文件，经本机接口调用同一套实验函数，不能成为第二份项目数据库。现有 CLI 保留为辅助入口；前端不重新实现 agent runner。

接口只监听 127.0.0.1。所有 API 核对随机令牌，所有请求核对 Host，写入另核对精确 Origin；不允许 CORS，静态资源白名单，CSP 禁止外部脚本与嵌入。配置/实验路径拒绝越界、符号链接和目录联接。认证内容、任意文件、命令执行及原始异常轨迹没有页面接口。F1 的所有操作不调用模型。

当前 API：`GET /api/state`、`/api/environment`、`/api/profiles/<name>`、`/api/experiments/<id>`；`POST /api/profiles/save`、`/api/profiles/import`、`/api/profiles/restore`、`/api/plans/preview`、`/api/plans/create`。写请求使用 JSON。预览返回短期 preview_id 与输入指纹，保存前重新核对；所有配置写入另建名字，不覆盖源。历史默认最多显示最近 100 份，可手动刷新。不存在启动/停止接口。

前端视觉合同：白色内容区、浅灰背景、单一蓝色 #002FA7、系统无衬线字体、细分隔线；桌面左导航，窄屏顶部横向导航。表格按内容滚动，状态同时用文字表达，支持键盘焦点和减少动态效果偏好。页面必须呈现真实来源与缺值，不能用虚构成功或百分比填空。若交由其他工具改视觉，应保持上述操作/数据合同，接回功能时不新增另一份状态数据库。

总览中的“实验任务进度”来自当前计划的实际 trial 状态；“产品开发进度”以 ROADMAP.md 的阶段验收为准，二者不能混用。只在里程碑完成、需要用户审查或真实阻塞时交接；用户审查路线后，在约定阶段内连续完成实施与验收，不每做一个内部步骤就要求继续。

## 配置合同

每套配置有 `profile.json`、`config.toml`、`AGENTS.md`，可选 `skills/<name>/SKILL.md`。

当前原生设置白名单：`model_reasoning_effort`、`web_search`。模型在实验层指定。首轮固定搜索 disabled、固定推理档位。未知字段拒绝，MCP 等后续能力明确未支持。

每次 plan 复制配置和题目；执行前核对快照与 runner 摘要。源 profile 修改不影响旧快照；旧快照被手工修改则禁止执行。重复执行已产生的 attempt 会报错，建立新计划保留旧记录。

内容寻址提供可检测的不可变性，不等于操作系统不可写：本机所有者可以改文件，但校验能发现差异。计划本身目前不是签名包。

`config import-current` 只读取当前 home 下显式 AGENTS.override.md/AGENTS.md 和 config.toml，将白名单字段与指令保存成私有 profile。非空 override 优先；`--reasoning` 可显式固定推理档位，搜索固定 disabled。回执逐项列出归一化和省略设置，但不保存省略设置的值。MCP、插件、信任记录和认证不复制。不得宣称完整复制个人 harness。

`config clone --skill` 只添加用户选定目录，保留源、哈希；`config restore` 校验历史哈希后生成新私有名字，原始指令、原生配置和 skills 字节不变，profile.json 的名称变化。所有操作都不覆盖宿主配置或旧实验。可移植导出包尚未实现。

全局指令上传到独立 CODEX_HOME；skills 上传到独立容器 HOME 的 `.agents/skills`。容器无用户个人目录。上传成功与实际使用分开记录：校验指令文件哈希是装载证据，最终回复中的 profile 标记是遵循该指令的观察证据，不能据此推断每条规则都被遵循。

原生系统 skills 仍属于固定 Codex 二进制提供的环境；不能宣称“零 skills”。初始两套示例不附加用户 skills。

多轮时 HOME 保留同一 trial 的 skills，下一轮注入前必须与上一轮预期清单完全一致；每轮上传后再次核对全部用户 skill 哈希。首次运行要求目录为空。skill 读取证据要求成功的命令事件、SKILL.md 路径和完整正文均出现于工具输出；没有读取不能伪报使用，读取也不能证明全部遵循。

## 题库与验收

先验证原创小题，后续接入经验证的 SWE-bench Lite 固定子集。每题记录来源、许可、revision、group、环境、约束和是否改编；第三方工具许可不等于题目许可。

原创工作流路线保留四类：复用现有能力、替换并清理旧实现、连续需求变更、局部修改与回归。不能只选让代码越少越占优的题；也要保留合理复杂任务。

公开材料包含参考解和验收规则，但运行时 agent 只获得起点代码与当前题面。Git 未来历史、验收器、其他 trial 和完整 benchmark 不进入工作容器。候选代码导出整个 /app，包含新增和删除；验收时覆盖全新容器的 /app，避免只取 diff 漏掉 untracked 文件。

Harbor 的验收容器在 agent 结束后建立；题目的 verifier 文件预先打入独立验收镜像，不进入 agent 镜像，agent 修改自己的 tests 不会替换外部验收器。只使用公开题面明确的约束，不以隐藏审美偏好扣分。

本工具验证正常编码 agent 的效果，不对蓄意攻击验收器的任意恶意代码提供安全承诺。

`storage-migration-v1` 是两条预先固定的用户消息：第一轮在既有 JSON 存储上新增归档；第二轮迁到 SQLite，原子校验并导入旧数据，清理 legacy_store.py、旧 backend/path 设置和陈旧文档，保留第一轮行为、既有测试及规范化工具。每轮单独导出 /app 并在全新验收容器检查；验收结果不回灌 agent，下一轮题面事先固定。两轮都通过才算任务通过，缺轮、终止事件缺失或 session ID 不连续会明确失败。

这道题的首轮明确要求“如有 brainstorming skill 则使用”，两套配置题面一致。这只验收显式技能读取，不能据此声称已测自然触发或普遍收益。

`csv-catalog-v1` 属于独立的 catalog-import 任务组，代码起点与笔记题分开。只给一条固定用户消息，要求修复惰性 CSV 解析、字段与重复 SKU 校验、JSONL 原子替换和 CLI 错误行为；保护既有校验工具和回归测试。失败输入必须保留旧目标字节，成功时也不能直接截断重写正在使用的目标文件。外部验收包含受控逐行输入与 Python 文件访问观察；不以文件数量或代码行数评分。题面不显式点名 skill，单次有无读取观察不用于估计自然触发概率。

## 实验协议

- 每个独立任务和重复使用新环境、新会话；题内两轮启用 Harbor resume_trajectory，并检查两轮事件中的 session ID 相同。
- 固定同一镜像 ID并建立内容标签保留，防止便捷标签重建后丢失旧 manifest；首次构建耗时与 agent 时间分开。
- 一份计划支持两个 profile 和选定的多道题；按指定任务顺序，相邻题反转 A/B，下一次重复再次反转。重复不是新任务，没有随机性结论。
- 每用户轮 agent 300 秒；单轮题两套总上限 600 秒，两轮题两套总上限 1200 秒。三个现有题各重复一次，共 6 次整题运行、8 轮、2400 秒 Agent 上限。计划按每题轮数计算总预算，环境准备和验收另算。token/账单没有硬预算控制，不声称有。
- 无自动重试。环境异常后先停止，修因后新建 attempt；历史不删。
- 首版使用固定用户消息，不引入随机 AI 用户或临时人工救场。
- 允许访问模型服务域名，其余出站受 Harbor allowlist 控制；验收断网。远程模型别名和服务端缓存无法完全冻结。

schema 3 的 `tasks` 按题名保存 group、step_names、两类镜像 ID 和文件摘要，源材料位于 `inputs/tasks/<题名>`；profiles 在批内共用同一份冻结快照。每条 trial 显式引用题名、profile、repeat 和该题的总预算。执行前验证全部快照、题目定义与路由元数据相同、计划覆盖/顺序和总轮数/预算一致；后面的题若被改动，也在首次模型调用前拒绝。

只把当前 trial 对应的题目路径传给 Harbor，按该题是否有 steps 决定 resume_trajectory；不会将多题合并为一条会话。旧 schema 1/2 的 `inputs/task` 通过兼容读取继续用于报告和历史分析，原计划不迁移改写。旧 runner 摘要与当前代码不一致时仍须新建实验，兼容读取不代表可以用新代码续跑旧计划。

## 保存和展示

`runs/<experiment>/plan.json` 固定配置哈希、任务哈希、runner 摘要、镜像、模型、版本、预算和顺序；`inputs/` 保留材料；`trial-*/harbor/` 保留框架完整产物；每 trial 的 `result.json` 为清晰摘要；HTML 可重新生成。

`comparison.json` 与 HTML 按计划中的 group 汇总整题运行：计划数、通过、未通过、异常、待完成；按 `(task, repeat)` 配对同批两套配置，只合计双方都通过的 Agent 秒数，同时保留配对覆盖数。没有成功配对或对应耗时不完整时为 null，不用零填补。逐次结果保留题名、顺序、重复序号和完整证据；按组汇总不删除失败行，不从旧实验借用缺失结果。报告重新分析时，新的 comparison.json 也仅写入新分析目录。

结果区分：完成通过、完成失败、超时、执行异常、基础设施异常、验收异常、续接协议异常、未开始。拿不到的用量/耗时是 null，不能写 0；订阅使用不套 API 单价冒充真实费用。更精细的限流和交互阻塞分类留待有真实事件证据后补充。

逐轮报告展示验收、执行秒数、配置第几次装载、skills 文件数、完整读取证据、增量用量与产物入口。每轮原始 `turn.completed.usage` 保存在 reported_usage；单轮原样读取 CLI 上报。多轮只有通过以下全部条件才产生总量和增量，否则所有派生用量为 null 并记录 reason：

1. 预期轮数完整且执行完成；各轮唯一原生 session 文件的 ID 与事件中的 ID 相同，CLI 版本为已验证的 0.154.0。
2. 各轮 token_count 历史为上一轮的完整前缀扩展，且各计数非负、不回退。
3. 每轮 CLI 累计值与原生记录末值一致；缓存输入不大于输入，存在 total_tokens 时等于输入加输出。
4. 各轮取相邻累计差值；最终总量取最后累计值。cached_input_tokens 是 input_tokens 的子集，不再次相加。未知版本、多会话、坏 JSON、缺字段或计数矛盾均不猜测。

`usage_accounting` 保存方法、源会话文件哈希与状态；当前不把 reasoning 等子项再次加入输出，不计算订阅账单。usage 校验失败与任务行为验收是不同状态，不能把缺用量改判成行为不合格。

`chb analyze` 只处理已结束实验，校验冻结输入，在 `.local/analyses/<唯一编号>/` 新建派生结果、分析版本和报告。来源清单包含输入、原结果/报告及 agent 日志，分析前后哈希相同才完成。新报告链接原始证据，原计划与原报告均不改写；如果重新解析改变通过/失败状态则停止。修正分析器与重新执行任务是独立操作，历史分析也不覆盖。

Harbor 0.23.0 多轮顶层 verifier_environment_mode 原生为空，本工具单独注明来源为冻结 separate 协议，并提供逐轮验收日志，不能伪称这是上游返回的非空字段。

所有本地轨迹默认不提交 Git，不自动上传。公开发布结果需先审查日志中可能出现的配置和个人内容。

## 评分和误差

主指标为统一预算内关键验收通过率。速度必须同时展示失败和超时；比较速度时限制在双方成功的配对任务，并报告覆盖数。

任务链只算一道题，同题重复不虚增独立任务数。当前有三个声明任务组，来自同一套原创小题设计，其中搜索与存储有共同笔记工程背景，不能把 group 标签等同于统计独立性。当前仅输出描述性配对覆盖和耗时，不输出置信区间、显著性或总榜分。将来先审查来源关联并扩充任务，再以适当的独立来源组作配对重采样。

代码行数、文件数、工具次数是诊断信号，不直接扣分。主观设计质量可匿名审查，与行为验收分开展示。微量改动只能在多样任务和重复实验后判断；“未测出差异”不代表等效。调参集与冻结后的验证集应分开，公開保留集仍可能有训练污染。

## 复现与撤销

同机复测依赖保存的镜像 ID 和快照。跨机器完整复现仍需镜像分发或锁定 OS 软件包；基础镜像 tag 的重建不保证逐字节一致。使用 `chb prepare` 构建一次、随后 plan 固定实际镜像 ID。

停止测试不改用户全局 Codex 配置。代码以本地 Git 提交回退；实验目录先归档再移除。容器由 Harbor 清理；镜像留作复测缓存，删除时精确指定本项目镜像，不运行全局 Docker prune。
