当前有本地桌面评测工作流、5套具独立功能验收的源码题包、51道共用空白起点与基础烟检的原创网页题、12道各有独立文件起点但尚无独立程序验收的开放题，以及 DeepSWE 113 条可按题准备的来源索引。工作台默认显示24题跨类型精选；这是浏览候选池，不是已经校准或跑完的统计题集。Terminal-Bench、BrowserGym、τ³-bench、SWE-bench 四类目前只是来源与接入门槛研究，尚不可在本机作为题包执行。**五份既有 DeepSWE 回收已在固定上游 Linux 镜像完成原题验收**，本地连续分为 98.8、61.8、98.3、98.7、98.3，最近完整批次配置分为 91.2；这些分数不能外推到新题。另有一批五道真实前端交付从旧裁判模型不可用的未评状态恢复为5/5个本地AI辅助参考分，批次显示90.3；其中一题的裁判镜像缺少中文字形，尚不能比较细微视觉分差。现状和缺口见[U54题集审计](research/task-portfolio-audit-20260927.md)、[主架构第8.17节](PROJECT_SPEC.md#817-u57-草稿确认裁判失败诊断与短时前端空间题)与[当前交接](当前交接.md)。

## 如何区分事实、要求和提案

- **用户已定**：U07/U08/U10 或 D15 条目能直接支持的要求。
- **现有实现**：在当前代码中找到入口和行为；基准及交付版本见当前交接和历史；不等于所有情况已实测。
- **已验证**：有具体测试或操作回执，并明确验证范围。
- **目标合同**：依据用户要求补齐的设计；尚未编码的字段和接口必须写“拟新增”。
- **待审设计**：需要用户以后裁决的产品取舍；默认建议和影响写在所属模块，不把沉默当作批准。
- **未验证/不支持**：没有依据时直接这样写，不用“预留”包装为完成。

U46 评分方案已由用户在 U47 确认并进入运行代码。五题本地连续分与原题 reward 分存；最近完整批次在配置成绩页合成当前分。尚未接语义卡的公开题不生成本地总分，长期项目和视觉量表仍需继续校准。Gemini 原目录只读；完整对话原文、配置和实验产物留在 `.local/`。公开文档保存相关要求的整理和必要短引，不复制完整日记。

## 审查时值得先看的四个例子

1. 项目题有“刷新后数据仍在”这一要求：它应从选题、提示词一路进入验收明细；当前已接入并有软件链路验收，仍不等于正式桌面整题通过。见任务合同 T-AC1。
2. 配置要求每阶段等确认：等待应算遵守要求，不能自动扣效率分。见执行合同 E-AC3 与用量合同 M-AC2。
3. AI 说某文件缺少功能：路径与引用存在只证明引用正确，不能证明意见正确；需允许人工驳回并保留记录。见评分合同 S-AC5。
4. 两套配置只差一条规则：要看实际条件、任务版本和重复结果，单次高两分不构成可靠收益。见用量合同 M-AC4。

## 换新对话时从哪里继续

先读[当前交接顶部 U54](当前交接.md)、[PROJECT_SPEC 第8.14节](PROJECT_SPEC.md#814-u54-当前入口从题多转向任务机制多)和[U54题集审计](research/task-portfolio-audit-20260927.md)，再按任务读[评分](architecture/EVALUATION.md)、[题集](architecture/TASKS_AND_CONTRACTS.md)、[用量比较](architecture/MEASUREMENT_AND_COMPARISON.md)和[前端](FRONTEND_SPEC.md)。`requirements.md` 是用户要求保真记录，`CODEX_HISTORY.md` 是历史证据；旧章节所写“当前”仅代表当时状态。

新对话先按题集审计的“题面、独立起点、程序验收、真实成绩”四层核对事实。优先补独立数据/工程题的正负例与程序验收、至少一类非 SWE 公开基准的完整环境适配、创意题机制去重和盲评校准；24题精选在这些条件达标前不能称正式具名跑分套件。小分差须按同题配对、独立重复和条件报告，不靠多显示小数位。
