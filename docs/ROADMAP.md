# 当前路线图：前端优先的本地配置评测工具

## 目标与推进依据

用户打开本地工作台，保存/切换两套 Codex 配置，选择相同题目，看清差异与预算，运行对比、追踪异常、查看证据，再恢复历史配置复测。需求以 [R01–R23](requirements.md) 为准，当前交付证据以 [交接](当前交接.md) 为准。

R20–R22 提出后已给出五页与 F1–F4 方案。用户随后在 U06 要求继续并上传指定仓库；助手据此沿前端优先顺序实施。这是继续实施授权，不把它写成逐页视觉设计已获用户验收。旧的前端后置安排已替代，历史保留在 Git。

## 整体框架怎样运行

**浏览器操作 → 本机 Python 接口 → 配置与冻结计划 → Harbor/Codex 容器执行 → 独立容器验收 → 结果文件 → 页面查看/恢复。**

F1 已接通配置、计划和结果管理。中间的真实执行仍由 CLI 启动；将启动/停止和实时状态接入页面是 F2 的工作。页面复用同一套本地文件与实验函数，既有技术底座继续使用。分层与接口见 [架构合同](PROJECT_SPEC.md#产品全流程与前端合同)。

## 已验证与尚未验证

F1 浏览器实际完成：从 minimal 另存配置 → 选两套配置与三题 → 预览 6 次整题/8 轮/2400 秒 Agent 上限 → 保存计划 → 从冻结历史恢复新副本。数据写到实际 `.local/` 与 `runs/`，未创建模型 attempt，原配置未改变。自动检查、构建和布局证据见交接。

现有 CLI 曾分别完成三个原创题的模型验收；最近多题模型批次只完成 1 项通过、1 项额度异常、4 项未运行，成功配对数为 0。旧单题结果不能补齐新批次。任务分类不等于统计独立，两个笔记题尤其有共同来源。

## 连续实施方式与下一阶段

后续最高价值工作是 F2：先实现有归属的后台运行状态与防重入，再接启动/请求停止和容器清理，随后页面实时反馈，最后做一次真实新批次验收。先完成无需模型的接口与异常检查；模型额度只约束最后真实验收。

同一阶段内连续实现、联调和验证，达成验收或出现真实阻塞才交接；不要求用户为每个内部步骤再说“继续”。每次真实跑题先说明验证哪个尚未验证的假设，没有新问题则不重复消耗模型额度。

## 发布与限制

代码已上传 https://github.com/devonsagr/1 的 main；仓库可见性未修改且未核实，不宣称部署了公网网站。界面运行于本机，GitHub Pages 不能承载 Python/Docker 执行服务。

`runs/`、`.local/`、认证、私人配置与完整日记不提交。Obsidian 镜像模式 none，没有回写。支持的安装路径仍为克隆仓库后 uv sync；wheel 虽含前端资源，尚不含题目与示例配置，不作为独立完整分发包。
