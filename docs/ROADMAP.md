# 当前路线图

## 目标

使 Codex 配置变更可保存、比较和复测。需求依据为 [R01–R19](requirements.md)，有效架构为 [PROJECT_SPEC.md](PROJECT_SPEC.md)。

|阶段|范围|状态|
|---|---|---|
|0 方案核查|核查竞品、官方接口、本机条件，选一个执行底座|完成调研与底座运行验证；完整 skills 隔离实测留待下一阶段|
|1 最小闭环|两套配置、一题、独立验收、真实轨迹、静态报告|已完成：两次真实 Codex 运行均通过独立验收，见交接|
|2 配置历史|clone、restore、import/export、严格原生配置能力扩展|未开始|
|3 公开题库|固定 SWE-bench 子集、公开原创工作流题、多轮续接|未开始|
|4 可信比较|任务组配对统计、失败分类完善、逐题证据浏览|未开始|
|5 易用性|按需添加本地界面与结果包导出|未开始|

## 阶段 1 后的顺序

1. 验证一个携带 skill 的配置与无该 skill 配置之间的隔离和真实使用证据。
2. 增加一条固定多轮替换任务，检验旧入口/依赖/配置清理。
3. 完善配置恢复，再扩大任务多样性。不要先把单题重复次数拉高冒充任务覆盖。
4. 用户决定发布后才上传源码和任务，逐项确认公开题源与许可。

## 风险

当前原创题很小，只有一个独立任务组；不能比较微小配置收益。配置生效只能观察公开接口和日志，不可能完整证明模型内部行为。模型服务、订阅额度与网络状态是外部运行条件。容器 ID 可固定本机运行，跨机重建还需分发镜像和锁 OS 包。
