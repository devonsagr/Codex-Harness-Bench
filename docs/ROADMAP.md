# 当前路线图

## 目标

使 Codex 配置变更可保存、比较和复测。需求依据为 [R01–R19](requirements.md)，有效架构为 [PROJECT_SPEC.md](PROJECT_SPEC.md)。

|阶段|范围|状态|
|---|---|---|
|0 方案核查|核查竞品、官方接口、本机条件，选一个执行底座|完成调研、底座运行与选定 skill 的隔离实测|
|1 最小闭环|两套配置、一题、独立验收、真实轨迹、静态报告|已完成：两次真实 Codex 运行均通过独立验收，见交接|
|2 配置历史|clone、restore、import/export、严格原生配置能力扩展|部分完成：私有部分导入、clone、restore 与真实 skill 加载/读取验证；完整配置/导出包待做|
|3 公开题库|固定 SWE-bench 子集、公开原创工作流题、多轮续接|搜索、存储替换、CSV 导入三类原创题已实测；第三方子集及源码发布待做|
|4 可信比较|任务组配对统计、失败分类完善、逐题证据浏览|累计用量与逐轮增量已校验；历史日志可独立重分析；多题同批、分组统计尚未实现|
|5 易用性|按需添加本地界面与结果包导出|未开始|

## 当前顺序

1. 已完成：当前全局说明的私有部分导入，对比是否添加 brainstorming；实际观察到完整 skill 读取，两轮装载哈希一致。
2. 已完成：两轮存储替换题、跨轮同会话及独立验收；两套配置共四轮都通过。真实历史配置恢复也已验证。
3. 已完成：固定版本 resume 累计校验、增量展示及不改写历史的分析报告；独立代码起点的 CSV 导入题两套配置均通过。
4. 下一步：把现有题纳入一次冻结计划，按任务组展示同批结果和协议差异；不能直接拼接不同时期的旧实验来宣称配置收益。任务数量仍不足时不输出置信区间。
5. 配置扩展保留可移植导出及明确的能力边界；继续增加不同工程来源的任务，需要时才引入界面。
6. 用户决定发布后才上传源码和任务，逐项确认公开题源与许可。

## 风险

当前有三个小型原创任务组，但每次实验仍只有一个组；旧实验的配置、执行代码、任务与时间不同，不能直接合并计算配置收益。配置生效只能观察公开接口和日志，不可能完整证明模型内部行为。存储题观察到显式读取 skill；CSV 题未观察到完整读取，不能由这一题推断触发概率。模型服务、订阅额度与网络状态是外部运行条件。镜像 ID 与保留标签能支持同机复测，跨机重建还需分发镜像和锁 OS 包。用量计数核验只支持已验证的 Codex 0.154.0 协议，费用依然不提供账单估值。
