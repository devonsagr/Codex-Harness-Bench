# U69：把题源接成可检查的任务，而不是继续堆 AI 高分

## 用户要解决的问题

用户要求继续完成评分系统，搜集公开题库和社区常见测试，增加不同机制的小项目；不能只更新五道专项、罗列不可执行的来源，或让用户处理验收器故障。核心目标仍是同模型下，个人 Harness 是否提高交付并减少过度工程化、答非所问和人的负担。一般模型知识水平不是这个目标的替代指标。

这些是可追溯的一手项目和社区案例，部分是2024–2025年的经典测试，不能称为2026年最新流行榜。没有“爬完全网”的证据；也没有把网页上的热度或作者排名当作任务有效性证明。

## 本次实现

### HumanEval+：163道可运行题、123095个固定扩展输入

固定 release 提交 `200defce9e3429d28ca215b6dd061c0f7f31c18b`；gzip SHA-256 `daa7661c8189924068069b0872a440b491edb60f8bdf431d5957adc88d18bae5`。下载只在 `.local/arena/public-sources`，不随仓库分发。导入接口 `/sources/evalplus` 幂等，保留编辑和归档；每题只把原题函数起点 `solution.py` 交给桌面，不复制隐藏测试或参考解。

固定镜像采用 Python3.12/NumPy1.26.4，每次验收使用现有只读快照→容器副本、禁网、限CPU/内存/PID、删除容器链路。程序只执行固定上游断言，整套通过才判通过，不由AI挑样例。25秒子进程预算耗尽返回未验证。解释为本地桌面适配，不能称官方pass@k。短函数默认不进入项目随机组卷，避免大量小算法题稀释项目测量；可以手选用于简单任务的流程开销对照。

上游164题中32号的OriginFmt导出断言存在参数解包错误；本地诊断修正后，附带参考解及另一实现仍未通过全部导出输入。没有靠降低标准或改答案让它过关。最终发布保持其余原断言不变，并将32号排除在可运行集合之外。资格检查记录保留在本地；[上游也有 find_zero 特殊残差判定](https://github.com/evalplus/evalplus/blob/master/evalplus/eval/__init__.py)。这次接入163道，不宣传164道已经全部就绪。

统一离线 `index.html` + `model.js` 起点，核心使用公开的纯函数接口；不同实现共享同一固定测试，不需按每次模型作品调整断言。题面和用例在 `tasks/community-web-v1`，参考实现只用于忽略的本地QA。不是上游原题复现；允许自由布局和视觉风格，缩小了原社区任务规模。

另有真实Chromium检查控制入口/状态、页面调用核心、三种视口及脚本异常。这些只证明列明的页面事实，不证明按钮后的所有机制、审美或完整游戏。核心77项不能被包装成“所有前端需求已验收”。8题直接补入启动题库与32题精选，按机制分组随机；旧题和分数不覆盖。

### 分数到底表示什么

程序通过比例 = 通过固定用例数 / 全部固定用例数。分母不因缺项缩小；缺项、超时、错误协议、错误哈希、截断或矛盾回执留未知，不偷算高分。HumanEval+用整套0/100通过判定，展示扩展输入数，不把一套测试说成一个简单样例。无需AI和“结束交付”操作，当前回收快照完成检查即可看到结果；新快照不继承旧通过。

程序结果与AI参考分分开：AI高分不能把明确失败变通过。HumanEval+原扩展测试接入同模型A/B的程序交付统计；社区核心测试只认证核心，**不**把其通过变成整个网页已达标。现有真实对话观察仍按双方原话计数，语义准确率和视觉AI都未完成独立校准。

“绝对”只指固定任务合同内的通过事实；“相对”指同模型/题目/版本/预算/环境的A/B收益。不能把最强模型作品当作100分真值，或因Luna名字较弱就人为压分。不同题的核心通过百分比不是跨题库综合能力分。

## 验收记录与实际界限

资格检查包括全部163题参考实现/错误实现、8个社区正确核心、8个空实现及8类具体边界错误。测试覆盖当前协议和这些缺陷，不等于现实项目或视觉评分的通用准确率。实际模型桌面A/B收益、盲评误判率与提示词扰动仍须真实样本；此次未调用付费裁判。

接口与缓存、哈希、导入幂等、归档保护、未知/失败区分和旧快照独立性有回归测试；公开源码只提交适配器、原创题与文档，不提交数据包、参考答案、用户轨迹、配置和产物。实测数量/构建/浏览器回执见当前交接。
