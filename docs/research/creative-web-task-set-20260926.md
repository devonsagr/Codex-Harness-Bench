# 原创开放网页题集：来源、边界与使用方法（2026-09-26）

## 为什么不直接复制流行演示

[Simon Willison 的鹈鹕骑自行车 SVG 提示词](https://feeds.simonwillison.net/2024/Oct/25/pelicans-on-a-bicycle/)是一个直观的空间构图演示，但固定画面广泛传播，不能单凭这一题给模型/个人 Harness 排名。[Hugging Face OpenEnv 的可执行版本](https://github.com/huggingface/openenv/blob/main/docs/source/environments/pelican_svg.md)也明确指出原始组合已接近饱和，并把可解析、结构与视觉语义分层核验。于是本题集采用“水獭驾驶缆车”“鹈鹕骑单轮车送包裹”等**原创变体**；后者保留熟悉主题，但不能当成原版官方成绩。

[WebDev Arena](https://arena.ai/blog/webdev-arena)的真实用户题分布不止落地页，还包括游戏、仪表盘与交互应用；其体验优劣靠用户实际使用和偏好判断。[DesignBench](https://github.com/WebPAI/DesignBench)把生成、编辑、修复分成不同前端任务；[Interaction2Code](https://github.com/WebPAI/Interaction2Code)指出只看静态页面会漏掉交互。这里据此扩充场景，但**没有搬运那些题目、基准数据、权重或榜单成绩**。金门大桥、黄鹤楼只是用户提出的创作主题，本项目不声称它们是某个标准榜单题。

### 2026-09-27 流行任务型研究与本地改写

[近期 B 站 SVG 测评](https://www.bilibili.com/video/BV18wYv6eEMV/)展示了环形轨道的运动连续性和机械结构难点；[浏览器应用与 CAD 模型的上手测试](https://www.bilibili.com/video/BV1aHtj6gEhn/)涵盖浏览器操作系统、游戏和三维模型；[三维浏览器赛车演示](https://www.bilibili.com/video/BV16RbL6QEa6/)展示了可玩网页游戏的验证需求。[可运行的一次性应用对比仓库](https://github.com/VSBDev/one-shot-app-benchmarks)公开了游戏、餐厅、像素编辑器、室内平面规划的题面与浏览器/盲审方法。这些是选题形态线索，不是本项目直接复用的题目或评分。X 搜索未找到可核对的特定题面来源，因此没有以“X 热门题”名义入库。

新增十道本项目原创题：两个空间/机械 SVG 变体，两个三维与环轨交互，四个可操作工具，两个可玩游戏。它们均有明确的用户路径、失败或边界状态及观察点，保留视觉风格与实现路径自由；没有复制视频里的具体提示词、截图或参考解。题包的共用浏览器程序仍只做结构与一次交互的烟检，不会自动证明多窗口层级、完整游戏回合、几何尺寸、导出正确或空间连续性。这些须在回收版本上按题面实际操作并留证；若只有烟检，相关细项保持未测。

## 程序检查能证明什么

每题的 `checks` 使用共享 `chb-verifier:creative-web-v1`：在禁网容器中用 Chromium 打开候选 `index.html`，检查主标题、可见内容、控制台异常、390/1280px 横向溢出；依题型增加 SVG、图表、表单或一次可见交互的最低门槛。它是**基础烟检**，不是任务完成率或网页审美分。空白起点应失败；一个具备结构的合成样页可通过，说明脚本接线正常，**不说明它完成了任何一题**。实际内容是否满足题意、视觉效果、事实正确性、金额/时间逻辑、可访问性与“对话体感”仍需分别看页面、行为与证据，人工可复核主观判断但不能改写浏览器检查结果。

50 道创意题的不同可接受实现没有唯一参考解；当前未建立逐题多样化参考作品与盲评校准样本，不能宣称这 50 题都有等价于 DeepSWE 原题测试的自动验收。当前 Docker Linux 引擎若不可用，页面仍可直接打开，程序检查保持未验证，不记作零。成本、速度、重复稳定性与长期协作要在多次真实执行后按同一口径报告，不能由题面数量推算。

## 公开前端基准的下一步接入边界

[DesignBench](https://github.com/WebPAI/DesignBench)公开了前端生成、编辑、修复的评测代码与数据入口，覆盖原生 HTML、React、Vue、Angular；其仓库说明 900 个网页样本，但依赖另行下载的数据与 Linux/浏览器环境。我们目前仅借鉴**任务类型**，没有把那 900 个样本算作本地可运行题。[Interaction2Code](https://github.com/WebPAI/Interaction2Code)关注交互原型到网页，仓库说明 127 个页面、374 个交互；它也不能直接作为本项目的离线开发工作区题包。[WebDev Arena](https://arena.ai/blog/webdev-arena)的分类研究表明网页设计、游戏、应用、3D 图形等不同任务表现差异明显，其用户偏好分数不能转换为本地单题程序分。后续引入公开数据时必须逐题核对授权、冻结输入与资源、建立可运行起点和对应验收，再从“来源索引”升级为“可选题”；不能只把网页链接加进题库数字。

## 建议的低预算抽样

先固定四种不同能力各一题，如矢量空间、互动网页、数据图表、表单流程；同一配置/预算运行后再按缺口补题。要判断很小的 Harness 差异，应在同题配对重复并盲审，而非靠 50 道题的数量制造一位小数的确定感。熟知的“鹈鹕骑自行车”原题不进入默认主分；若使用其变体，也应标明它是探索性题，不把它与其他原创题或公开排行榜混同。
