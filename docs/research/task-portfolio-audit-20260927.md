# 题集重复性、覆盖与公开基准接入审计（U54）

核对日期：2026-09-27。本文区分**可看见的题面**、**可创建的起点**、**可运行的独立程序验收**和**已有真实评测分数**。这四种数量不能互相代替。用户指出“题多但换汤不换药”的原因是真实的：此前 50 道创意题共享同一个空白 HTML 起点和六种粗粒度浏览器烟检，12 道集中在 SVG 插画；展示数量曾压过其他类型，且“原创网页与插画”和“网页与全栈”两个入口重复覆盖同一批网页题。

**U57 增补**：现有创意目录为51题，新增 `mini-exhibit-3d-v1` 是一页短时、离线、可旋转的三维展台，要求真实视角与前后遮挡；它用基础 `interactive` 烟检，不能由该烟检证明三维正确。24题精选保留一项金门大桥交互SVG，以新展台替换水獭缆车；旧题可在全库选择，已冻结的旧 Run 不变。下方“50题/水獭为精选”的叙述是 U54 当时的审计快照，以本段和当前 JSON 题单为现行入口。网页着陆页、数据仪表盘、小游戏、像素工具和表单仍是不同机制；这些不是都在做 SVG。后续入选需看可操作结果与验证证据，而非热点关键词。

## 2. 重复性判据与这次取舍

审题不能只比较标题或题面词汇。对于每个候选，记录五个向量：起点与真实输入、可观察的主要交付物、核心操作/状态变化、独立验收证据、预算与失败模式。若五个向量只在故事角色或颜色上变化，归为同一**变体簇**；不应在低预算核心集里并列占多道。若两题同样是 SVG，但一题考空间遮挡、一题考完整设计系统，虽然技术共享，仍可保留为不同机制。

|此前常见重复|保留在精选的代表|其他题现状|后续入池要求|
|---|---|---|---|
|动物＋交通工具的 SVG 场景|水獭缆车：空间路径与角色关系|鹈鹕、狐狸、海豹等仍在全部题中可查|需证明新的空间/状态机制，而非换动物|
|地标＋日夜/季节切换|金门大桥：叙事状态与视觉层级|黄鹤楼及其他地标保留为探索变体|需有不同交互或约束，不能只换建筑名|
|宣传页/展览页/品牌故事|虚构展览页：内容层级和响应式|其余保留为扩展创作|验证信息架构差异，不靠风格词增题|
|工具/游戏仅换主题|像素编辑器、救援游戏|其它工具/游戏仍可自选|画布状态、导出、回合规则等必须有实质不同|

当前尚未实现自动语义去重、题目相似度分数、动态抽样或对“同机制”结果的重新加权。这些需要真实模型交付和人工盲审，不应按标题自动合并旧成绩。本轮只建立审计口径、固定精选和入口减法。

## 3. 新开放题到底补了什么

[open-work-v1/catalog.json](../../tasks/open-work-v1/catalog.json) 只保存题面、类型、阶段和人工复核点；`environment/<id>/` 每题各有不相同的文件，不复用空白网页起点。程序任务要求保留或扩展现有入口，业务题有具体 CSV/政策冲突，长项目题用三个阶段分批给要求，协作题交付可审查的决定/交接。当前没有参考解、隐蔽验收器、已校准盲评或真实评分；因此这些题只能称“有独立起点、可运行正式桌面流程的开放题”，**不能**称“12 道已验证基准题”。AI 审查按冻结评分卡给有引用的参考意见，人工可复核；缺少证据时依旧留空。

|群组|题目 ID 与主差异|主要证据|
|---|---|---|
|业务与数据|refund-exceptions：冲突规则；field-dispatch：容量/跨区；subscription-cohort：重复事件/留存口径；incident-log：乱序证据|案例结果、逐项追溯、错误/未知边界|
|工程与可靠性|event-schema：协议兼容；retry-idempotency：重复副作用；cache-retention：路径与恢复；latency-budget：正确性/性能取舍|代码、测试、复现命令、限制说明|
|长期与协作|stock-migration：阶段性迁移；community-scheduler：逐轮新规则；stakeholder-scope：冲突优先级；incident-handoff：事实/假设分层|阶段快照、最终回归或交接文档、明确未决项|

长项目每阶段仍属同一个 Trial，不能把三个阶段当作三道独立题或三次独立重复。若用户选默认“完整需求单次交付”，系统会在开始时给出所有阶段；要测真实需求变更应显式选分阶段，并在后一阶段才发新要求。后续必须在 UI 中更明显地标出这一差异。

## 4. 公开来源研究与适配边界

以下只登记官方仓库与适用性，没有把其他基准的题包、镜像、验收器或参考解加入产品与被测工作区。前端来源区同样标为“接入评估”，数量不计入可选题。当前优先评估 Terminal-Bench，因为已有 Harbor 裁判基础；这只是技术优先级，不代表已接通。

|上游|为什么值得研究|与本产品不同的地方|达到“已接入”之前必须验证|
|---|---|---|---|
|[Terminal-Bench 2.0](https://github.com/harbor-framework/terminal-bench-2)|终端、系统、数据和科研工作流，超出 SWE 仓库修题|每题是固定容器环境及官方测试；本项目正式执行在 Codex 桌面|固定版本/许可、答案隔离、Linux 镜像、桌面起点可操作、原验收起点失败/参考通过、回收后原分单列|
|[BrowserGym](https://github.com/ServiceNow/BrowserGym)|WebArena Verified/VisualWebArena 等浏览器操作专项|测**使用**既有网页，而非开发网页；需运行站点及可重置状态|浏览器任务协议、网站重置、动作和截图轨迹、实际成功判定、任务版本|
|[τ³-bench](https://github.com/sierra-research/tau2-bench)|多轮业务对话、政策约束和工具/API 使用|模拟用户、域 API 与状态，不是普通文件工作区|固定用户/政策/数据库、工具调用轨迹、重置、原有指标；不能仅贴题面|
|[SWE-bench](https://github.com/SWE-bench/SWE-bench)|DeepSWE 之外的真实 GitHub 问题，含多模态方向|仍主要是软件工程，不能代替业务、协作或前端原创质量|固定 instance/commit、依赖/镜像、隐藏测试与官方结果口径；与 DeepSWE 分源|

榜单截图中 GPQA、HLE、数学/医学等是知识或学科专项，未必适合“Codex 桌面交付真实项目”的主分；可以未来做独立专项，不能把百分比抄进本地成绩。公开网页演示题同理是灵感，不是免校准的基准。每个来源的许可证与目标工程许可必须分别核对，官方排行榜协议不同不能并成一个“综合分”。

**Terminal-Bench 单题适配勘查（未接入）**：2026-09-27 在忽略的 `.local/qa/terminal-bench-2-upstream` 仅读取上游固定提交 `2fd12b88aafdd04a52c298e3940bcb189f9766d6`；顶层许可证为 Apache-2.0。检查了 `log-summary-date-ranges`、`constraints-scheduling`、`count-dataset-tokens` 的题面、`task.toml`、容器定义与 `tests/test.sh`，未执行上游解法或验收，也未将其安装到本项目题库。首选 `log-summary-date-ranges` 属日志汇总数据任务，题面给固定参考日期、要求写入容器 `/app` 下的 CSV；输入日志在上游镜像**构建时生成**，不是仓库中的普通工作区文件。另两题分别依赖 ICS 文件和在线 Hugging Face 数据集，后者还需要下载 tokenizer，不适合作为首个离线可复现样本。

现有桌面导入器接收文件起点，现有容器检查器把回收快照复制进 `/app` 并禁网；Terminal-Bench 的正式协议由 Harbor 创建原题环境，再将测试包单独挂到 `/tests`，其 `test.sh` 运行时在线安装 `uv` 与 pytest。直接复用当前检查器会失去镜像内的日志或因禁网缺依赖；把测试放进桌面起点又会泄露验收内容。先要写专用适配器：固定上游提交和镜像内容摘要；从镜像仅提取允许交给模型的输入并对照哈希；保留测试与参考解在私有缓存；预构建离线 verifier 依赖或在隔离准备阶段获取；对空白起点及可靠正例各跑一次；最后对桌面回收快照按官方路径执行并保存原始 reward、日志、版本和环境差异。此路径未实现，页面继续标“接入评估”；Docker Linux 当前可连接，只是环境前置条件之一，不能由此推断原题已可运行或有分数。

**正式适配验收表**：固定 URL/commit/许可证 → 只下载选中任务且校验哈希 → 起点与验收器分存 → 环境预检并可复跑 → 起点负例、参考或可靠正例通过 → 桌面工作区真实交付回收 → 上游分与本地质量分并列显示 → 在来源详情给版本、环境、耗时与失败原因。未走完的状态依次为研究、索引、源码就绪、环境就绪、原验收验证、真实试次；任何一步不得跳写“已测”。

## 5. 评分与抽样的目标

单题按冻结评分卡给可追溯具体分；配置成绩先同题重复均值、再不同题等权。雷达六轴只是同一证据的诊断视图，不重算总分。新增开放题没有程序检查时，程序项是“未配置/未测”，不能按失败零分；AI 与人工能否形成完整分取决于实际回收、引用与该题适用项，不能仅因已选入精选就点亮雷达。

为小差异做低预算比较时，应从不同机制选一小组固定题、两套配置在相同题目版本与环境下配对，再少量重复。精选 24 道是**浏览候选池**，不是默认要求全做 24 道；不得回看成绩后挑对自己有利的题。要宣称“稳定提升”，需记录独立重复、差值波动、成本和人工介入；只看一次小数差不够。长期项目另看最终交付与阶段回归，不把每轮当独立样本。

## 6. 未解决清单与验收标准

1. **题面真实区分度**：精选已按输入/输出机制做编辑筛选，但没有真实跨模型交付样本。收集至少两种实现、人工盲评一致性及“换皮变体”复核，再冻结具名题集版本。
2. **开放题程序检查**：12 道新题有独立起点但无独立程序裁判。先为数据和工程中可确定的部分补隔离验收与负/正例；业务、协作与长期题的开放目标继续保留逐项人工/AI 证据，不强行 0/1。
3. **非 SWE 公开基准**：目前只是四个上游的接入评估。优先选择 Terminal-Bench 中一题，完成上表全链路，再扩展；BrowserGym、τ³ 等须独立 runner/环境合同，不伪装为当前任务。
4. **结果展示**：新的图表布局已在本机 1440px、390px 和深色模式浏览器实测；深色成绩卡文字对比度已修。尚未用新增开放题的真实模型交付检验分轴取证与人工可读性；六轴中未测仍留空。所有综合分只在实际评测证据齐备时出现。

本研究的数量和状态来自当前代码与本机验证，不应以“页面有入口”外推出官方榜单成绩。
