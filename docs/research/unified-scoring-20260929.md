# 统一评分方法研究与实现取舍 · 2026-09-29

## 结论

可以统一数据流、原始需求覆盖、等级定义、证据规则和算分；不能用一个裁判随口打出的百分数替代各基准自己的原验收，也不能靠降低所有分数解决虚高。项目现在落地前者，仍需保留样本验证后者。UI应明确“参考判断”和“程序检查事实”的来源。

## 本轮可复用的机制

每道新审查自动生成固定需求编号，原文不丢失，模型无权自由删减；所有评分维度使用coverage/quality/resilience同一格式。0–4有明确等级锚点，4须有主动反例引用，分数程序计算。原题失败/未验证限制目标维度，没有extra奖励；固定卡仍决定各题权重，避免用户逐题调比例。程序判定的是报告结构、引用归属、证据存在和算式，不代替语义理解。

原始任务可能包含非功能要求和相互冲突的条款：裁判应记录冲突/不适用原因而不捏造测试。当前requirementChecks仍有met/partial/unmet/unverified四态，不自动删去无法判断项；这可能带来弃评分，需用校准样本衡量。长题面最多48组但组内不删句；条件密集的组更难判断，不能当成更高精度。

最高档必须“有反例证据”仍可能被弱裁判误判，例如日志是真实的但与需求无关；不同引用只是最低程序门槛。因此本轮不能以模型返回完整JSON就宣布正确。缺少反例不能机械补75；等级3也须明确次要缺陷并有正向依据。

## 后续质量验收，不是继续堆提示词

1. 冻结不同机制的匿名好/坏/边界交付，保留未参与规则开发的样本；视觉由多人独立判并记录分歧。
2. 在相同快照、题面、模型/档位/速度和环境重复；单独改变提示词表达，观察分项波动与排序逆转。
3. 统计关键缺陷漏检、高分误判、弃评率、解析失败率、同条件实际极差与代价；报告失败，不只平均值。
4. 对程序事实用确定性检查替代AI意见；对主观项无法达标时展示分项证据与相对比较，不发布伪精确总分或机械压低分数。

这些需要真实独立裁判与人工锚点，尚未完成；本轮未擅自重复付费调用。默认GPT-6-Luna/max保留，模型能力与题目难度应通过上述数据判断，而不是先假定便宜模型应得低分。
