# 配置、版本与实际装载合同

负责 D15-02/05/07/11/17/20；关联 [数据接口](DATA_AND_API.md)、[比较条件](MEASUREMENT_AND_COMPARISON.md)。现有实现含用户级/项目级配置导入、Skills 面板与冻结装载；剩余工作见主架构 B03/B06。

## 1. 用户要管理的是什么

配置应让人看懂“本次打算让 Codex 按什么方式做事”，并能在以后调出同一份内容。模型、档位、规则、技能、交互约定和个人约束分别呈现，不能只展示一个名字和分数。

|配置内容|现有存储/装载|目标细则|
|---|---|---|
|名称、说明、作者|save_config 白名单保存|说明不包含预设优劣或成绩|
|模型 baseModel|校验标识格式，读取本机模型缓存供选|展示缓存来源与可用性待核对；不能宣称所有模型支持所有档位|
|推理 reasoning|保存枚举，工作区装载/显式全局应用，桌面实际档位仍需核对|按模型能力提供建议；缓存过期、未知组合有明确提示|
|AGENTS 正文|文本版本，写入工作区 override；显式全局应用时备份并替换全局 override|展示原文和实际生成内容，不能把“已保存”当“已遵守”|
|skills|导入文件、清单和哈希，配置引用导入 ID|显示名称、内容版本、来源、文件数；同名不同内容明确区分|
|interactiveMode|adaptive / one-shot-direct / step-by-step-confirm|提示词中表达约定，阶段操作保持人工确认|
|customConstraints|ID、标题、规则、启用状态；列表随配置冻结|补类别、验收方式和证据说明；见第4节|
|specialFeatures|后端允许保留，当前 UI 没有编辑/装载语义|原型的 antiScopeCreep 等不能成为只影响分数的空开关；迁移为明确规则或标记停用|

原型 skills 只有名字；当前导入真实文件是必要改进。原型的类别、规则差异和约束说明则不应因为实现真实导入而消失。

## 2. 导入、保存、修改、恢复

配置导入仅放在配置管理；评测准备只选择已保存版本并预览规则、原生设置、工具开关和技能。临时Skills调整仍只进入本次Run。准备页使用统一技能面板，来源/搜索/勾选在同一处，勾选时自动冻结并选中；配置管理保留批量导入。配置正文使用独立预览，不堆叠在选择区。

1. 新建配置得到新 ID 和 revision=1。编辑必须携带已读取的 revision；过期提交拒绝，保留用户草稿，不自动覆盖。
2. “另存副本”生成新 ID。它是新候选，不表示已经测过，也不继承旧分数。
3. “导入当前全局规则副本”一键读取 CODEX_HOME（未设置时为 ~/.codex）内优先的 override/AGENTS 和模型/档位、白名单原生设置及已配置工具的启用开关。也可指定项目根，预览该层规则与 .codex/config.toml 后导入；保存来源/哈希、默认值说明，不复制认证、MCP命令、插件安装文件或依赖。项目导入不是完整继承链解析。
4. Skills 面板读取选定来源，显示名称、用途、路径和版本，支持搜索、多选、批量冻结并加入配置草稿。选择保存的是快照 ID；重复导入同一来源/内容复用快照，源文件变化不改变旧评测。
5. 从历史 Run 恢复配置生成新副本。当前已有新ID与“历史副本”名称，但缺少显式恢复来源元数据；目标需补来源Run/配置revision关系。配置页也还没有所有revision的时间线和任意旧版恢复入口。
6. 归档不删除；恢复归档只改变可见性。归档与创建新副本不能都叫“恢复”而不说明区别。

目标版本页面应提供：版本时间线、正文差异、技能清单差异、约束差异、使用过该版的历史记录、恢复为新副本。数据库已有 revisions 表不等于这些产品功能已经完成。

### Skills 来源与调用

|来源|读取位置|本次使用方式|
|---|---|---|
|用户级|`~/.agents/skills`；同时列出本机 `$CODEX_HOME/skills` 兼容目录|勾选后冻结，不改全局文件|
|指定项目|该根目录 `.agents/skills` 与 `.codex/skills` 兼容目录|只读取指定项目，不扫描整个磁盘|
|自定义技能库/插件来源|用户指定的库或具体技能目录|复制技能文件；不安装其插件、MCP 或其他依赖|
|评测试次|`workspace/.agents/skills/<name>/`|准备时自动放入，运行页显示来源和实际位置|

用户级 `.agents/skills` 与项目级目录、按描述匹配/明确请求两种用法依据 [OpenAI Skills 文档](https://learn.chatgpt.com/docs/build-skills)。本机兼容目录不代表唯一全局路径；插件缓存文件存在不代表插件启用。面板不把所有插件缓存自动加入技能列表。

扫描最多四层/500目录/200技能，需有效 name/description；链接、凭据和超限条目不可导入。同名项并列显示，配置保存时只允许选一个；起点已有同名技能会在创建目录前提示冲突。未选全局技能仍可能由桌面继承，不宣称已禁用。

配置可选“按任务需要使用”或“每轮明确请求使用”。prepare 把技能名称、具体 SKILL.md 路径与使用意图加入 Trial 的冻结提示词，不复制完整技能正文，也不伪造原生 Skill 选择标记。文件装载和提示词请求不等于实际触发；实际使用看执行证据。旧 Run 不追加新提示。

工作台允许本次调整Skills及调用方式，不改已存配置。prepare核对来源revision，只在Run的配置快照保存实际选择及preparationOverride（原revision/技能/调用方式）；两套对比各自独立，未知技能、同名、过期版本在创建目录前拒绝。新工作区应用入口不写宿主配置，不承诺桌面热切换。

## 3. 工作区规则如何生成

现有 prepare 的顺序：自动创建试次目录 → 复制题目起点 → 读取起点根 AGENTS/override → 拼接配置正文与启用约束 → 追加交互约定 → 写 `AGENTS.override.md` → 写 `.codex/config.toml` 的模型/档位/受支持设置 → 复制选定技能到 `.agents/skills/<name>/` → 初始化独立 Git → 冻结 baseline。用户不需要手动建目录或复制文件；配置与题目均可保存后直接带入评测。

需要区分三份东西：用户保存的配置原文、题目起点本来带的规则、准备后实际生成的工作区文件。配置差异页只比第一份还不够，执行前应能查看第三份。

### 已知边界

- 导入和准备工作区不写全局；只有用户点击应用才写本机配置。认证不迁移，未选择的设置保持宿主值。
- 独立 Git 目录并不消除宿主全局规则、技能和插件的影响。
- 当前宿主指纹只覆盖全局 AGENTS.md、AGENTS.override.md、config.toml；不能当成完整环境指纹。
- 当前回收比较规则、选定技能及工作区 .codex 文件的变化；变化是条件证据，不代表具体哪条规则造成成绩变化。
- 文件装载、模型读取、技能触发、最终遵守是四个不同命题。当前可确认装载文件与部分日志条件，不能自动证明后三者。

### 目标中的冲突提示

若起点规则要求不改某目录，而配置要求重构该目录，不能静默拼接后声称配置有效。B03 要显示来源与可能冲突，由用户选择新配置/新题版本或添加解释；不自动裁决用户规则，也不修改历史。

## 4. 个人约束怎样处理

个人约束是本次实验合同的一部分，不是通用好坏标准。例如镜像同步只在该用户启用时验收；要求先讨论再编码时，按要求等待是合格行为。

拟新增的约束细则：

|字段|含义|
|---|---|
|id / title / ruleDesc / isActive|延续现有字段，ID 稳定|
|category|文档与文件、确认与交互、同步、范围、其他；仅帮助组织|
|verificationMode|人工、可执行检查、证据辅助；不能默认为自动|
|acceptanceHint|怎样观察符合或不符合，例如哪份文件或哪次确认|
|importance|用户声明的必要/建议级别；初期不自动换成通用总分|

验收记录每条有 met / unmet / unverified / not_applicable、说明和证据引用。版本2已保存各条constraintNotes，未核实可无依据，已裁定需说明。not_applicable 必须说明为何本题不适用，不能用来隐藏失败。

原型的 weightPoints 可保留为导入来源信息，但不能不经定义就加到通用分。若以后支持个人专属评分，必须独立命名、冻结策略，并与不同人的结果分开。

## 5. 配置对照矩阵

目标恢复 Gemini 的可读矩阵，增加实际版本证据。至少有这些行：模型、推理、交互约定、AGENTS 正文变化、技能新增/移除/内容变化、个人约束启停/内容变化、题目起点规则、宿主条件已知差异。

每行状态为相同/不同/未知；文本差异可展开，技能不能只比名字。矩阵先列不同项，再提供全部条件。它说明变量发生了什么，不声称已经建立因果关系。

当前准备页可切换配置查看规则、约束及本次技能，可以查看内容，但没有真正的字段矩阵、正文差异高亮或技能内容对照。该缺口不是纯视觉优化。

## 6. 问题与决定

|编号|疑问|处理与依据|
|---|---|---|
|C-Q1|保存和应用是否同一步？|普通保存只进工作台；“保存并一键应用到Codex”另有明确出口，备份后写原生配置。文件写入不等于已有桌面任务已切换|
|C-Q2|导入全局规则是否完整替换？|不。界面明确标为副本和叠加层；严格替换全局环境暂不支持|
|C-Q3|个人要求怎样公允量化？|先按本次启用条目留证据，不把个人偏好加到公共分；是否另开个人分是待审设计|
|C-Q4|为何不能只保留两个 JSON？|用户要求简单调换、清楚对照。能读原始数据不等于完成配置比较交互|

## 7. 验收案例

- **C-AC1**：A/B 模型相同但一个技能内容不同且名称相同，矩阵显示内容变化和哈希，不判为完全相同。
- **C-AC2**：修改配置后查看旧 Run，仍显示旧正文和旧技能文件；恢复得到新 ID，不改变原 Run。
- **C-AC3**：导入全局规则后，宿主文件哈希不变；页面明确哪些字段已导入、哪些需要手动核对。
- **C-AC4**：两页同时编辑，后提交过期版本不能覆盖，用户输入仍能复制或另存。
- **C-AC5**：启用“阶段等确认”，实际工作区文件可查看该规则，人工验收能引用确认记录；未启用配置不被强制要求同样行为。

## 8. 工作台配置应用到 Codex

入口有两个：配置页“保存并一键应用到Codex”使用刚保存的版本；评测详情“应用本题冻结配置”使用Run快照（含本次Skills调整）。普通导入、保存、选题不产生宿主写入。切换时先按哈希撤销上一应用，再写新配置，避免残留技能叠加；失败保留回执并说明已撤销旧应用。

|组成|本轮行为|
|---|---|
|模型、推理、联网搜索、输出详略、推理摘要|写入CODEX_HOME/config.toml；保留注释、未知键和认证|
|AGENTS、交互约定、个人规则|所选内容写全局AGENTS.override.md，原文件私有备份；原AGENTS.md不改|
|Skills|冻结文件放到CODEX_HOME/skills；同名同内容复用，不同内容拒绝；撤销只处理本次写入文件|
|MCP、插件（含Superpowers）|按本机config.toml已有ID选择继承/启用/停用；不复制工具命令、密钥，不把启用标志当安装完成|
|权限/沙箱、Hooks、记忆、子代理、其他项目层|属于环境条件，本轮不迁移；保持宿主值，不宣称整个Harness已完整导出|

私有codex-applications目录保存应用前字节和写入后摘要；多文件写入失败尝试回滚，进程中断留下可恢复记录。撤销前核对所有相关文件，有外部修改即拒绝覆盖。记录/接口不返回备份正文或凭据。一个宿主同时只保留一份活动应用；工作台记录正在执行时不允许切换。

新工作区另生成.codex/config.toml，让模型/推理/原生设置随试次冻结。受信任项目才加载项目层；已有任务覆盖、重载/重启、组织策略仍可影响有效配置。UI状态为“文件已写入”，正式执行前仍核对桌面实际值。对准备态试次的显式应用保留原hostFingerprint，并记录appliedHostFingerprint及应用ID，后续回收按应用后的预期值检查；不改旧回收。

依据：[OpenAI配置层](https://learn.chatgpt.com/docs/config-file/config-basic)、[配置字段](https://learn.chatgpt.com/docs/config-file/config-reference)、[Superpowers安装入口](https://github.com/obra/superpowers#codex-app)。


应用状态同时区分历史回执与当前文件：/codex/status对活动应用返回fileChecks、filesMatch及当前全局instructionsFile，仅读取；不输出文件正文、认证或备份。文件变化不自动推断某个设置失效，也不强制覆盖。页面可手动“核对当前文件”，显示匹配/变化的相对路径；已写入不等于桌面当前任务已采用。

本工具写AGENTS.override.md并保留原AGENTS.md，因此Codex个性化页可能继续显示原文并提示被override覆盖。该提示与官方[全局规则优先级](https://learn.chatgpt.com/docs/agent-configuration/agents-md)一致，不是应用失败。检查全局文件后仍需区分项目覆盖与当前任务设置，开发时不自动修改用户日常配置。
